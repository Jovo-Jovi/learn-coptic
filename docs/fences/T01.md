### What this task is

learn-coptic is live in production. Its code works and stays as it is. DEV_OS's checks (`devos.config.json`
`required_checks`: guards, typecheck, lint, test, build) cannot run on it today, for three reasons:

1. The cycle and `ci` install with `pnpm install --frozen-lockfile`, which refuses a project that has only
   `package-lock.json`. Nothing installs, so no check runs.
2. `package.json` has no `typecheck` and no `test` script, and `run-checks.mjs` records a missing script as a failed
   required check.
3. `pnpm run lint` runs `eslint` over the whole repository, DEV_OS's own method files included, which no product task
   may change (`surfaces.builder`); a finding there could never be fixed by a task.

This task fixes exactly those three things, and nothing else. It builds no feature and changes no product code.

### Prompt

Preconditions: the tree is clean; `main` holds the adoption commit (`docs/PHASES.md` exists with T01 open); Node 22.
In the automated profile the runner owns git (PR-04): run no `git add/commit/push` and no `gh`.

**STEP 1 — Read.** Read the context above. Run `node scripts/devos/fence-check.mjs docs/fences/T01.md`; HALT on a
finding.

**STEP 2 — The pnpm lockfile (fix 1).** In the repository root run `pnpm import`. It reads `package-lock.json` and
writes `pnpm-lock.yaml` with the same resolved versions. Do not edit, regenerate or delete `package-lock.json`: it
stays the lockfile of the developer's `npm` and of the Vercel deploy (OD-05). Then run
`pnpm install --frozen-lockfile`; it must exit 0. pnpm may print that it skipped some dependencies' build scripts;
that is a note, not a failure, unless a later check fails because of it (then HALT, see the STOP block).

**STEP 3 — The two missing scripts (fix 2).** In `package.json` `scripts`, add exactly these two entries and change
nothing else in the file (no dependency, no version, no other script, no `packageManager` field):

- `"typecheck": "next typegen && tsc --noEmit"`. Why: `tsconfig.json` includes `.next/types/**/*.ts`, where Next.js
  generates the global `PageProps` and `LayoutProps` helpers that `src/app/layout.tsx` and the eight dynamic pages use;
  `run-checks.mjs` runs typecheck before build, so without `next typegen` the types do not exist yet. If the
  documentation in `node_modules/next/dist/docs/` names a different command for generating those types in 16.3, use
  the documented one and report the change (the generator's documentation wins).
- `"test": "tsx --test \"tests/**/*.test.ts\""`. Why: Node's own test runner, through `tsx`, which is already a
  devDependency, so no package is added. The explicit glob keeps DEV_OS's `scripts/devos/screens.test.mjs` out of the
  product's tests.

**STEP 4 — One architecture test (so the test check has a test to run).** Create `tests/architecture.test.ts` with
one `node:test` test, using only `node:test`, `node:assert/strict`, `node:fs` and `node:path`. It reads every `.ts`
and `.tsx` file under `src/lib/` and `src/data/` and asserts that none imports the UI: no specifier that starts with
`@/components` or `@/app`, and no relative specifier that resolves into `src/components/` or `src/app/`. On failure the
message names the file and the specifier. This rule holds in the code today (the logic and the data sit below the
UI, `docs/STACK.md` §3); the test must pass on the code as it is. Add no other test: T02 and T03 own the unit tests.

**STEP 5 — Lint the product only (fix 3).** In `eslint.config.mjs`, add these five entries to the existing
`globalIgnores([...])` list, after the entries that are there, and keep every existing entry and comment:
`"scripts/devos/**"`, `"scripts/guards/**"`, `"devos/**"`, `".devos/**"`, `".cursor/**"`. Add a one-line comment above
them: `// DEV_OS's method files: checked by the engine, never changed by a product task.` Change no rule.

**STEP 6 — Prove it.** Run, in this order, and keep each exit code and the last lines of its output for the report:
`pnpm run typecheck`, `pnpm run lint`, `pnpm run test`, `pnpm run build`, then
`node scripts/devos/run-checks.mjs --strict`. The build's log must show the `prebuild` validator (`npm run validate`)
finishing with its ✓ line for the 32 letters; copy that line into the report. Read `.devos/ci-results.json` and list
every check with its status.

**STEP 7 — Close out, as the project's own rule says (`.cursor/rules/10-step-closeout.mdc`).**

  developer's merge of G-Checks. Do not rewrite an older entry.

- `docs/SESSION_CONTEXT.md` and `docs/DEVELOPMENT_JOURNAL.md`: update as their own headers say.

**STOP — HALT (stop, change nothing more, report):**
