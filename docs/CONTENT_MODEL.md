# Content model — learn-coptic

All content is JSON in `src/data/json/`, shaped by the Zod schema in `src/data/schema/index.ts` and checked by
`npm run validate` before every build (OD-13). HTML is never the database. The developer owns every content change
(OD-07); no agent edits `src/data/json/` to make a check pass, and no agent invents a letter, word, gloss,
transliteration, key or codepoint (`docs/STACK.md` §6).

## 1. The files

| File | Entity (`docs/GLOSSARY.md` §1) | Holds today | Read by |
|---|---|---|---|
| `letters.json` | `Letter` | 32 letters, one home group each (groups total 5/4/4/7/4/5/3), Arabic names, `athanasiusKey`, pronunciation `rules[]` and notes, letter audio | `src/lib/letters.ts` |
| `words.json` | `Word` | 11,858 rows: the 147-row teaching set (121 lexicon, 11 drill, 15 name), the Andreas harvest, the unique Thabet lemmas; `normalized`, `lemma`, `published` | `src/lib/words.ts` |
| `prayers.json` | `Prayer`, `PrayerLine` | 4 prayers (`khen-efran`, `lords-prayer`, `thanksgiving`, `psalm-50`), each line Coptic + Arabic + tokens; `startSec`/`endSec` for synced audio | `src/lib/prayers.ts` |
| `curriculum.json` | `Level`, `Lesson` | Level 1 (the seven letter groups) complete; Level 2 stubbed | `src/lib/curriculum.ts` |
| `grammar-rules.json` | `GrammarPoint` …, `GrammarAffix` | the owner's 10/10 grammar notes; 13 affixes `parseReady` | `src/lib/grammar-rules.ts` |
| `pronunciation.json` | `PronunciationFile` | two pronunciation systems, diphthongs, jinkim, pitfalls, reading drills | `src/lib/pronunciation.ts` |

Generated by the validator, never by hand: `src/data/generated/search-records.json` (the search index, read by
`src/components/WordSearch.tsx`) and `src/data/generated/hygiene-report.json` (the S16 report).

## 2. Routes and what they show

| Route | Shows | From |
|---|---|---|
| `/` | the promise in one Arabic line, then "ابدأ من المجموعة ١" | `curriculum.json`, `letters.json` |
| `/alphabet`, `/alphabet/[group]`, `/group/[id]` | the 32 letters as one grid, by group | `letters.json`, `curriculum.json` |
| `/letter/[id]` | the glyph (upper and lower), its Arabic name, rules, audio, example words, previous and next | `letters.json`, `words.json` |
| `/vocabulary`, `/vocabulary/group/[id]`, `/vocabulary/letter/[id]` | tap-to-reveal word cards, filters by group and letter | `words.json` |
| `/search` | Fuse.js over letters, words and prayer titles | the generated index |
| `/practice`, `/practice/group/[id]` | reading drills and a tap-to-reveal deck | `words.json` |
| `/quiz` | Leitner quizzes: glyph→sound, sound→glyph, word→meaning (teaching set only) | `letters.json`, `words.json` |
| `/prayers`, `/prayers/[id]` | the four prayers with tap-a-word highlighting | `prayers.json`, `words.json`, `grammar-rules.json` |
| `/about` | font, content and audio licences; how to contribute | — |

The phases add the grammar and pronunciation lessons (T06, T07, module `src/features/lessons`), word art on teaching
cards (T10, `src/features/word-art`) and synced audio on one prayer page (T11, `src/features/prayer-audio`).

## 3. Rules every content change keeps

- **Unpublished stays hidden:** `published: false` words never show.
- **A drill is not a dictionary word** (OD-17): it is marked تمرين قراءة — مش كلمة في القاموس, and may have
  `meaning: null`.
- **The teaching set is the quiz and art scope** (OD-28): harvest Arabic is never quizzed.
- **Prayer tokens never guess** (OD-29, OD-31): null is better than a wrong gloss.
- **A schema change is a decision**: it stops at the developer's gate (OD-07) and needs a reason in its fence.
  S15 needs none ("if one seems necessary, stop and ask").
- **Bulk edits by script**, which refuses to write on a mismatch and never overwrites a stored row (OD-32).
- **Every source is credited and licensed** (`docs/sources.md`, `docs/security.md`, `/about`).
